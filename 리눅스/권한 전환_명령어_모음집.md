# 리눅스 명령어 모음집 — 개인 권한 → 그룹 공용 권한 전환

## 플레이스홀더

| 표기 | 의미 | 예시 형태 |
|---|---|---|
| `<USER>` | 작업 계정 | 개인 로그인 계정 |
| `<GROUP>` | 공용 그룹 | 팀 단위 공유 그룹 |
| `<DATA_ROOT>` | 데이터/로그 상위 디렉터리 | `/data/collect` 등 |
| `<TARGET>` | 권한을 변경할 대상 경로 | `<DATA_ROOT>/subdir` |
| `<PROJECT>` | 작업 디렉터리 | `~/myproject` |
| `<SCRIPT>` | 실행 스크립트 | `worker.py` |
| `<SERVICE>` | systemd 서비스명 | — |
| `<DELIM>` | 로그 필드 구분자 | 다문자 구분자 가능 |

## 0. 가장 자주 쓸 5개

```bash
id                                  # 내가 어떤 그룹인지
ls -l                               # 소유자·그룹·권한 확인
sudo chgrp -R <GROUP> <TARGET>       # 그룹 변경
sudo chmod -R g+w <TARGET>           # 그룹 쓰기 허용
umask 002                           # 앞으로 만드는 파일을 664/775로
```

## 1. 권한 상태 확인

```bash
id                                  # uid, gid, 소속 그룹 전체
groups                              # 소속 그룹만
getent group <GROUP>                # 그룹 구성원 확인
ls -l                               # 파일 목록 + 권한
ls -ld <TARGET>                     # 디렉터리 '자신'의 권한 (d 옵션 필수)
ls -l --full-time                   # 초 단위까지 시각 표시
stat <파일>                          # 권한·소유자·atime/mtime/ctime 전체
stat -c '%A %U:%G %n' *             # 간결 출력: 권한 소유자:그룹 이름
namei -l <TARGET>/<파일>             # 경로 각 단계 권한을 한 줄씩 ★
```

**`namei -l`이 권한 문제 진단의 핵심입니다.** 최종 디렉터리 권한이 맞아도
중간 경로에 `x`(통과 권한)가 없으면 접근이 막히는데, 이걸 한눈에 보여줍니다.

### 권한 표기 읽는 법

```
-rw-rw-r--  1 <USER> <GROUP>  ...
│└┬┘└┬┘└┬┘
│ │  │  └── others : r-- (읽기만)
│ │  └───── group  : rw- (그룹원 수정 가능)
│ └──────── owner  : rw- (소유자)
└────────── 종류    : -=파일, d=디렉터리, l=심볼릭링크
```

| 숫자 | 파일 | 디렉터리 | 의미 |
|---|---|---|---|
| 644 | `rw-r--r--` | — | 소유자만 수정, 나머지 읽기 |
| 664 | `rw-rw-r--` | — | **그룹도 수정 (협업용)** |
| 755 | — | `rwxr-xr-x` | 소유자만 파일 생성 |
| 775 | — | `rwxrwxr-x` | **그룹도 파일 생성·삭제 (협업용)** |
| 2775 | — | `rwxrwsr-x` | 775 + setgid (새 파일이 그룹 상속) |

## 2. 소유자·그룹 변경

```bash
sudo chgrp <GROUP> <파일>            # 그룹만 변경
sudo chgrp -R <GROUP> <TARGET>       # 하위 전체 (-R 재귀)
sudo chown :<GROUP> <파일>           # chown으로도 그룹만 가능
sudo chown <USER>:<GROUP> <파일>     # 소유자+그룹 동시
sudo chown -R <USER>:<GROUP> <TARGET>
sudo chown --reference=<기준파일> <대상>   # 다른 파일과 같게 맞추기
```

**주의:** `-R`은 되돌리기 어렵습니다. 운영 경로에서는 먼저 대상을 확인하세요.

```bash
find <TARGET> ! -group <GROUP> -printf '%p %u:%g\n' | head -50   # 대상 미리보기
```

## 3. 권한(모드) 변경

```bash
sudo chmod 664 <파일>                # 숫자 지정
sudo chmod g+w <파일>                # 그룹 쓰기 추가 (기호 방식, 안전)
sudo chmod g-w <파일>                # 그룹 쓰기 제거
sudo chmod -R g+w <TARGET>
sudo chmod g+s <TARGET>              # setgid: 새 파일이 디렉터리 그룹 상속 ★
sudo chmod +t <TARGET>               # sticky: 소유자만 삭제 가능 (실수 방지)
```

### 디렉터리와 파일에 다른 권한 주기 (중요)

`chmod -R 664`를 디렉터리에 걸면 `x`가 사라져 디렉터리에 못 들어갑니다.
**반드시 분리해서 적용하세요.**

```bash
sudo find <TARGET> -type d -exec chmod 2775 {} +   # 디렉터리 → 775 + setgid
sudo find <TARGET> -type f -exec chmod 664 {} +    # 파일 → 664
```

또는 대문자 `X`를 쓸 수 있습니다. 단 `X`는 **"디렉터리 + 이미 실행 권한이 있는 파일"**에
적용되므로, 실행 파일(.sh, .py)이 섞여 있으면 그 파일에도 그룹 실행 권한이 붙습니다.

```bash
sudo chmod -R g+rwX <TARGET>        # 편하지만 실행파일에도 x가 붙음
```

> **함정:** 최상위 디렉터리에 `x`가 없으면 `find`가 하위로 내려가지 못해
> `Permission denied`와 함께 **일부만 적용되고 끝납니다.**
> 이럴 때는 최상위부터 먼저 열어주세요.
> ```bash
> sudo chmod u+rwx,g+rwx <TARGET>
> sudo find <TARGET> -type d -exec chmod 2775 {} +
> sudo find <TARGET> -type f -exec chmod 664 {} +
> ```
> 적용 후 `find <TARGET> -type d ! -perm -g+w` 로 누락분을 확인하면 확실합니다.

## 4. umask — 앞으로 만들 파일의 기본 권한

```bash
umask                               # 현재 값 확인 (0022 = 644/755)
umask 002                           # 이 셸에서만 664/775로
```

**영구 적용** (다음 로그인부터)

```bash
echo 'umask 002' >> ~/.bashrc
source ~/.bashrc                    # 지금 셸에 즉시 반영
```

| umask | 새 파일 | 새 디렉터리 | 용도 |
|---|---|---|---|
| 022 | 644 | 755 | 기본 (그룹 수정 불가) |
| **002** | **664** | **775** | **그룹 협업 (권장)** |

> **핵심 구분:** 새 파일의 **그룹**은 setgid가, **쓰기 비트**는 umask가 결정합니다.
> 둘 다 설정해야 `-rw-rw-r-- ... <GROUP>`이 나옵니다.

## 5. 그룹 협업 디렉터리 세팅 (레시피)

```bash
sudo chgrp -R <GROUP> <TARGET>                     # 1. 그룹 지정
sudo find <TARGET> -type d -exec chmod 2775 {} +   # 2. 디렉터리: 그룹쓰기+setgid
sudo find <TARGET> -type f -exec chmod 664 {} +    # 3. 파일: 그룹쓰기
echo 'umask 002' >> ~/.bashrc                      # 4. 이후 생성물도 664/775
```

**기존 root 소유 파일을 그룹 공용으로 전환**

```bash
find <TARGET> -user root -printf '%p\n' | head     # 대상 확인
sudo chgrp -R <GROUP> <TARGET>
sudo find <TARGET> -type f -user root -exec chmod g+w {} +
```

## 6. 권한 오류 진단 (PermissionError / Permission denied)

```bash
id                                  # 내가 그 그룹인가
ls -ld <TARGET>                     # 디렉터리에 그룹 w가 있는가
namei -l <TARGET>/<파일>             # 중간 경로에 x가 빠졌는가 ★
sudo -u <USER> touch <TARGET>/test   # 해당 계정으로 실제 쓰기 테스트
sudo -u <USER> cat <파일> > /dev/null # 읽기 테스트
```

**체크리스트**

| 증상 | 원인 | 조치 |
|---|---|---|
| 파일 생성 불가 | **디렉터리**에 `w` 없음 | `chmod g+w <디렉터리>` |
| 디렉터리 진입 불가 | 경로에 `x` 없음 | `chmod g+X`, `namei -l`로 확인 |
| 기존 파일 수정 불가 | 파일이 644이거나 다른 소유자 | `chmod g+w <파일>` 또는 `chown` |
| 그룹 추가했는데 안 됨 | 세션에 미반영 | **재로그인** 또는 `newgrp <GROUP>` |
| 새 파일이 계속 644 | umask 022 | `umask 002` |
| 새 파일 그룹이 계속 root | setgid 없음 | `chmod g+s <디렉터리>` |

> **꼭 기억할 두 가지**
> 1. **삭제·이름변경 권한은 파일이 아니라 상위 디렉터리의 `w`에서 나옵니다.**
>    디렉터리가 775면 그룹원이 남의 644 파일도 지울 수 있습니다 → 걱정되면 `chmod +t`.
> 2. **파일 소유자는 생성 시점에 그 프로세스 계정으로 고정됩니다.**
>    나중에 다른 계정이 append 해도 소유자는 바뀌지 않습니다.

## 7. 프로세스 관리

```bash
ps -ef | grep <SCRIPT>              # 프로세스 찾기
ps -p 1234,5678 -o pid,ppid,user,cmd  # 특정 PID 확인 (ps는 쉼표 OK)
pgrep -af '<SCRIPT>'                # PID + 커맨드라인
kill 1234 5678 9012                 # 정상 종료 (SIGTERM) — 공백 구분, 쉼표 불가 ★
kill -9 1234                        # 강제 종료 (최후수단)
pkill -f '<SCRIPT>'                 # 패턴 일치 전부 (먼저 pgrep으로 확인!)
sudo kill 1234                      # root 소유 프로세스
```

> `ps -p`는 쉼표를 받지만 **`kill`은 공백만** 받습니다. 이걸 혼동하면
> `arguments must be process or job IDs` 오류가 납니다.

### ps -ef 컬럼 읽기

```
UID     PID     PPID  C  STIME  TTY  TIME  CMD
root    239631  1     0  Jun15  ?    ...
        └PID┘   └PPID┘
```
두 번째가 PID, 세 번째는 부모 PID입니다. 붙여 읽지 않도록 주의.
**PPID가 1이면 systemd 관리 대상** → `kill`해도 재시작될 수 있음.

### 백그라운드 실행

```bash
Ctrl + Z                            # 포그라운드 작업 일시정지

# 처음부터 분리 실행 (권장)

```

## 8. 파일·디렉터리 조작

```bash
pwd                                 # 현재 경로
cd -                                # 직전 경로로 토글
readlink -f <파일>                   # 절대 경로 (링크 해제)

cp -r <원본> <대상>                  # 폴더 복사
cp -a <원본> <대상>                  # 권한·소유자·타임스탬프 보존 (백업용) ★
rsync -av <원본>/ <대상>/            # 대용량·재시작 가능
mv <파일> <대상>                     # 이동/이름변경
mv <파일> ..                         # 상위 폴더로 (.. = 한 단계 위)
mv -i <원본> <대상>                  # 덮어쓰기 전 확인
rmdir <빈디렉터리>
```

**`cp -a` vs `cp -r`:** 권한·그룹을 그대로 옮겨야 하면 `-a`를 쓰세요.
`-r`은 umask에 따라 권한이 바뀝니다.

## 9. 로그 확인 (실무 조합)

```bash
tail -f <로그>                        # 실시간
tail -f <TARGET>/$(date +%Y%m%d%H).log  # 시간별 롤링 로그 따라가기 ★
tail -100 <로그>                      # 마지막 100줄
wc -l <로그>                          # 줄 수
du -sh <TARGET>                       # 용량
df -h <DATA_ROOT>                     # 디스크 여유
watch -n 5 'ls -l <TARGET> | tail -5' # 5초마다 갱신 (생성 확인)

grep '<패턴>' <로그> | head
grep -c '<패턴>' <로그>                # 매칭 건수
grep -v '<패턴>' <로그>                # 제외
zgrep '<패턴>' <로그>.gz              # 압축 로그
```

### 다문자 구분자 로그 파싱

구분자가 **정규식 특수문자**(`| ^ . $ * + ? ( ) [ ] { }`)를 포함하면
`awk -F`에서 각 문자를 `\\`로 이스케이프해야 합니다.

```bash
# 예: 구분자가 세 문자이고 특수문자를 포함하는 경우
awk -F'<이스케이프한DELIM>' '{print $2, $4, $7}' <로그>

# 필드 개수 확인
awk -F'<이스케이프한DELIM>' '{print NF; exit}' <로그>

# 특정 필드 기준 집계 (7번째 필드)
awk -F'<이스케이프한DELIM>' '{c[$7]++} END {for (k in c) print k, c[k]}' <로그>
```

**더 안전한 방법 — 탭으로 치환 후 파싱** (이스케이프 실수 방지)

```bash
sed 's/<DELIM>/\t/g' <로그> | awk -F'\t' '{print $2, $7}'
```

## 10. 검색

```bash
find <TARGET> -name '*.log'                    # 이름
find <TARGET> -type f -mtime -1                # 24시간 내 수정
find <TARGET> -type f -size +100M              # 100MB 초과
find <TARGET> ! -group <GROUP>                 # 그룹이 다른 것 ★

find <TARGET> -perm 644 -type f                # 권한이 정확히 644
find <TARGET> -type f -mtime +30 -delete       # 30일 초과 삭제 (주의!)
grep -rn '<패턴>' <TARGET>                     # 하위 전체 내용 검색
```

## 12. 실수 방지 체크리스트

- `chmod -R 664`를 **디렉터리에 쓰지 마세요.** `x`가 날아가 진입 불가 → `find -type d/f` 분리
- `-R`로 소유자·권한을 바꿀 때는 **먼저 `find`로 대상 확인**
- 데몬이 사용하는 경로의 권한 변경은 **서비스 동작에 영향**을 줄 수 있음 → 담당자 확인
- 그룹 추가 후 **재로그인** 필요 (`id`로 반영 확인)
- `pkill -f`는 패턴이 넓으면 자기 셸까지 죽임 → **반드시 `pgrep -af`로 먼저 확인**
- `kill -9`는 파일이 잘릴 수 있음 → 먼저 일반 `kill`
- `find ... -delete`는 되돌릴 수 없음 → `-print`로 먼저 확인

## 13. 문서 공유 시 주의

이 문서를 팀 외부와 공유할 때는 다음 정보를 플레이스홀더로 유지하세요.
개별 항목은 민감도가 낮아도, 모이면 인프라 정찰 정보가 됩니다.

- 서버 호스트명, 계정명, UID/GID, 그룹명
- 내부 IP 주소 (사설 IP도 포함)
- 데이터·로그 절대 경로, 디렉터리 구조
- 내부 스크립트·서비스·프로파일 이름
- 로그 포맷 구분자, 필드 순서
