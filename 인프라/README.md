# 인프라

서버·클러스터 운영에 필요한 명령어, 점검 절차, 장애 대응 기록을 모아둔 저장소입니다.
"무엇을 칠 수 있나"(명령어 모음)와 "그때 왜 그렇게 했나"(장애 기록)를 함께 남기는 것을 목표로 합니다.

## 상황별 바로가기

| 상황 | 볼 곳 |
|---|---|
| `Permission denied` / PermissionError | 리눅스 명령어 → 권한 오류 진단 |
| 팀 공용 디렉터리 권한 세팅 | 리눅스 명령어 → 그룹 협업 디렉터리 세팅 |
| 계정 생성, 그룹 추가, sudo 권한 부여 | 리눅스 명령어 → 계정·그룹 관리, sudo 권한 관리 |
| 디스크가 계속 참 | 디스크 용량 분석 → 빠른 진단 순서 요약 |
| 무엇이 늘었는지 날짜별로 비교 | 디스크 용량 분석 → 스냅샷 비교 |
| 파드가 CrashLoopBackOff / Evicted | k3s 명령어 → 파드 상태별 의미, 로그 |
| 파드 안 로그 파일을 서버로 꺼내기 | k3s 명령어 → 파드에서 파일 추출 |
| containerd 이미지가 디스크를 차지 | k3s 명령어 → k3s·컨테이너 런타임 |

## 작성 규칙

**파일·폴더명**
- 영문 소문자 + 하이픈 (`disk-usage-analysis.md`). 한글 파일명은 URL이 인코딩되어 공유가 불편합니다.
- 문서 제목은 파일 안의 `#` 헤더에 한글로 씁니다.
- 장애 기록은 `YYYY-MM-주제.md` 형식 (예: `2026-08-disk-full-k3s.md`).

**플레이스홀더**

실제 값 대신 아래 표기를 사용합니다.

| 표기 | 의미 |
|---|---|
| `<USER>` / `<GROUP>` | 계정 / 그룹 |
| `<HOST>` / `<IP>` / `<PORT>` | 서버 / 주소 / 포트 |
| `<TARGET>` / `<DATA_ROOT>` | 대상 경로 / 데이터 상위 경로 |
| `<SERVICE>` / `<SCRIPT>` | systemd 서비스 / 실행 스크립트 |
| `<NS>` / `<POD>` / `<DEPLOY>` | 네임스페이스 / 파드 / 디플로이먼트 |

**명령어 표기**
- 위험한 명령(`-R`, `-delete`, `rm -r`, `kubectl delete`)에는 확인용 명령을 바로 위에 함께 적습니다.
- 자주 쓰거나 꼭 기억할 명령은 주석 끝에 `★`를 붙입니다.

## 장애 기록 템플릿

`troubleshooting/` 에 새 문서를 만들 때 아래 틀을 복사해서 씁니다.

```markdown
# <장애 제목>

- 발생일: YYYY-MM-DD
- 대상: <HOST> / <NS>
- 상태: 해결 / 진행 중 / 벤더 문의

## 증상
무엇이 관찰됐는지 (알림, 오류 메시지, 수치)

## 원인
확인된 원인. 추정이면 "추정"이라고 명시

## 조치
실행한 명령과 결과를 순서대로

## 재발 방지
설정 변경, 모니터링 추가, 정기 점검 등

## 참고
관련 문서 링크
```

## 보안 주의

이 저장소는 **Private**으로 유지합니다. 개별 정보는 민감도가 낮아 보여도 모이면 인프라 정찰 정보가 됩니다.

커밋 전에 아래 정보가 실제 값으로 들어가지 않았는지 확인하세요.

- 서버 호스트명, 내부 IP(사설 IP 포함), 계정명, UID/GID, 그룹명
- 데이터·로그 절대 경로, 디렉터리 구조
- 내부 스크립트·서비스·네임스페이스·파드 이름
- 로그 포맷 구분자, 필드 순서
- sudoers 파일명과 계정 목록
- kubeconfig(`k3s.yaml`), 토큰, 비밀번호, API 키 — **절대 커밋 금지**

```bash
# 커밋 전 간단 점검: 사설 IP 패턴이 남아 있는지
grep -rnE '(10|172\.(1[6-9]|2[0-9]|3[01])|192\.168)\.[0-9]+\.[0-9]+' .
```
