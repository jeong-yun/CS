# 리눅스 명령어 모음집

권한 관리, 계정·sudo, 프로세스, 로그, 압축, vi, 시스템 상태 점검까지 실무에서 자주 쓰는 명령어를 정리했습니다.
디스크 용량 분석은 [디스크 용량 분석](disk-usage-analysis.md), 쿠버네티스(k3s)는 [k3s 명령어](../kubernetes/k3s-commands.md)를 참고하세요.

## 0. 플레이스홀더

| 표기 | 의미 | 예시 형태 |
|---|---|---|
| `<USER>` | 작업 계정 | 개인 로그인 계정 |
| `<NEW_USER>` | 새로 만들 계정 | — |
| `<GROUP>` | 공용 그룹 | 팀 단위 공유 그룹 |
| `<DATA_ROOT>` | 데이터/로그 상위 디렉터리 | `/data/collect` 등 |
| `<TARGET>` | 권한을 변경할 대상 경로 | `<DATA_ROOT>/subdir` |
| `<PROJECT>` | 작업 디렉터리 | `~/myproject` |
| `<SCRIPT>` | 실행 스크립트 | `worker.py` |
| `<SERVICE>` | systemd 서비스명 | — |
| `<DELIM>` | 로그 필드 구분자 | 다문자 구분자 가능 |
| `<HOST>` / `<IP>` | 원격 서버 | — |
| `<PORT>` | 포트 번호 | — |
| `<UID>` / `<GID>` | 숫자 사용자·그룹 ID | 컨테이너 소유 파일 등 |
| `<ALIAS_U>` / `<ALIAS_C>` | sudoers 사용자·명령 alias | — |

## 1. 가장 자주 쓸 명령

```bash
pwd                                 # 현재 위치
id                                  # 내가 어떤 그룹인지
ls -l                               # 소유자·그룹·권한 확인
sudo chgrp -R <GROUP> <TARGET>      # 그룹 변경
sudo chmod -R g+w <TARGET>          # 그룹 쓰기 허용
umask 002                           # 앞으로 만드는 파일을 664/775로
tail -f <로그>                       # 로그 실시간 확인
df -h                               # 디스크 여유
ps -ef | grep <SCRIPT>              # 프로세스 찾기
```

## 2. 기본 탐색·파일 조작

```bash
pwd                                 # 현재 경로
cd -                                # 직전 경로로 토글
cd ~                                # 홈으로
ls -alh                             # 숨김 파일 포함, 용량 K/M/G 표시
ls -lt | head                       # 최근 수정 순
readlink -f <파일>                   # 절대 경로 (링크 해제)
tree -L 2 <디렉터리>                  # 2단계까지 트리 (설치 필요할 수 있음)

mkdir -p <경로>/<하위>/<하위>          # 중간 경로까지 한 번에 생성
touch <파일>                         # 빈 파일 생성 / 수정 시각 갱신

cp <원본> <대상 경로>                  # 파일 복사 (예: cp part_error.txt /home/<USER>/)
cp -r <원본> <대상>                   # 폴더 복사
cp -a <원본> <대상>                   # 권한·소유자·타임스탬프 보존 (백업용) ★
rsync -av <원본>/ <대상>/             # 대용량·재시작 가능
mv <파일> <대상>                      # 이동/이름변경
mv <파일> ..                          # 상위 폴더로 (.. = 한 단계 위)
mv -i <원본> <대상>                   # 덮어쓰기 전 확인
mv <원본경로>/{*,.[!.]*} .            # 숨김 파일 포함 이동
find <원본경로> -maxdepth 1 -type f -exec mv -t . {} +   # 파일이 많을 때 (인자 길이 초과 회피)
rsync -av --remove-source-files <원본>/ <대상>/           # 다른 파일시스템 + 대용량 이동
rm -i <파일>                          # 삭제 전 확인
rm -r <디렉터리>                      # 디렉터리 삭제 (되돌릴 수 없음)
rmdir <빈디렉터리>
ln -s <원본> <링크명>                  # 심볼릭 링크

cat <파일>                            # 전체 출력
less <파일>                           # 페이지 단위 보기 (q 종료, / 검색)
head -20 <파일>                       # 앞 20줄
```

**`cp -a` vs `cp -r`:** 권한·그룹을 그대로 옮겨야 하면 `-a`를 쓰세요. `-r`은 umask에 따라 권한이 바뀝니다.
**`mv`와 소유자:** 같은 파일시스템이면 rename이라 소유자가 유지되고, 다른 파일시스템이면 복사+삭제로 동작해 소유자가 바뀝니다. 투입 후 `ls -l`로 확인하세요.

## 3. 권한 상태 확인

```bash
id                                  # uid, gid, 소속 그룹 전체
groups                              # 소속 그룹만
getent group <GROUP>                # 그룹 구성원 확인
ls -l                               # 파일 목록 + 권한
ls -ld <TARGET>                     # 디렉터리 '자신'의 권한 (d 옵션 필수)
ls -l --full-time                   # 초 단위까지 시각 표시
stat <파일>                          # 권한·소유자·atime/mtime/ctime 전체
stat -c '%A %U:%G %n' *             # 간결 출력: 권한 소유자:그룹 이름
namei -l <TARGET>/<파일>             # 경로 각 단계 권한을 한 줄씩 ★
getfacl <TARGET>                    # ls 출력 끝에 '+'가 있으면 ACL이 걸린 것
```

**`namei -l`이 권한 문제 진단의 핵심입니다.** 최종 디렉터리 권한이 맞아도 중간 경로에 `x`(통과 권한)가 없으면 접근이 막히는데, 이걸 한눈에 보여줍니다.

### 권한 표기 읽는 법

```
-rw-rw-r--  1 <USER> <GROUP>  ...
│└┬┘└┬┘└┬┘
│ │  │  └── others : r-- (읽기만)
│ │  └───── group  : rw- (그룹원 수정 가능)
│ └──────── owner  : rw- (소유자)
└────────── 종류    : -=파일, d=디렉터리, l=심볼릭링크
```

| 숫자 | 파일 | 디렉터리 | 의미 |
|---|---|---|---|
| 644 | `rw-r--r--` | — | 소유자만 수정, 나머지 읽기 |
| 664 | `rw-rw-r--` | — | **그룹도 수정 (협업용)** |
| 755 | — | `rwxr-xr-x` | 소유자만 파일 생성 |
| 775 | — | `rwxrwxr-x` | **그룹도 파일 생성·삭제 (협업용)** |
| 2775 | — | `rwxrwsr-x` | 775 + setgid (새 파일이 그룹 상속) |
| 440 | `r--r-----` | — | 소유자·그룹 읽기만 (sudoers 파일 표준) |

**디렉터리 권한 비트의 의미** (파일과 다름)

| 비트 | 디렉터리에서의 의미 |
|---|---|
| `r` | 목록 조회(`ls`) 가능 |
| `w` | **내부에 파일 생성·삭제·이름변경** 가능 |
| `x` | 진입(`cd`) 및 내부 접근 가능 |

- 권한 매칭은 소유자 → 그룹 → 기타 순으로 **한 클래스만 배타 적용**됩니다.
  (소유자가 아니고 그룹원이면 그룹 비트만 적용되고 others 비트는 보지 않음)

## 4. 소유자·그룹 변경

```bash
sudo chgrp <GROUP> <파일>            # 그룹만 변경
sudo chgrp -R <GROUP> <TARGET>       # 하위 전체 (-R 재귀)
sudo chown :<GROUP> <파일>           # chown으로도 그룹만 가능
sudo chown <USER>:<GROUP> <파일>     # 소유자+그룹 동시
sudo chown -R <USER>:<GROUP> <TARGET>
sudo chown --reference=<기준파일> <대상>   # 다른 파일과 같게 맞추기
```

**주의:** `-R`은 되돌리기 어렵습니다. 운영 경로에서는 먼저 대상을 확인하세요.

```bash
find <TARGET> ! -group <GROUP> -printf '%p %u:%g\n' | head -50   # 대상 미리보기
```

### 복사 + 소유자/권한을 한 번에 (`install`)

```bash
sudo install -o <USER> -g <GROUP> -m 644 <원본> <TARGET>/<파일명>   # cp+chown+chmod ★
sudo install -d -o <USER> -g <GROUP> -m 755 <TARGET>               # 디렉터리 생성판
sudo setfacl -m u:<USER>:rwx <TARGET>     # 폴더 권한은 그대로, 특정 계정에만 접근 부여
​```

### 사용자명 ≠ 그룹명인 환경 주의

개인 그룹(UPG) 방식이 아닌 공유 그룹 체계에서는 `chown <USER>:<USER>`가
`chown: invalid group`으로 실패합니다. `id <USER>`로 실제 그룹을 먼저 확인하세요.

### 남의 소유 디렉터리에 파일을 넣어야 할 때
애플리케이션·컨테이너가 소유한 데이터 디렉터리는 **소유권·그룹을 바꾸지 말고**
파일만 기존 규격에 맞춰 투입합니다. 소유권을 바꾸면 원래 프로세스가 쓰기를 잃거나,
컨테이너 재기동 시 원복되어 원인 추적이 어려워집니다.

​```bash
ls -l <DATA_ROOT>/<TARGET>/ | head -3        # 기존 파일 규격 확인
sudo install -o <UID> -g <GID> -m 644 <원본> <DATA_ROOT>/<TARGET>/
​```

실시간 수집 디렉터리라면 **원자적 투입** (쓰는 도중 읽혀 반쪽 처리되는 것 방지)

​```bash
sudo install -o <UID> -g <GID> -m 644 <원본> <TARGET>/.tmp_<파일명>
sudo mv <TARGET>/.tmp_<파일명> <TARGET>/<파일명>   # 같은 디렉터리 내 mv는 원자적
​```

## 5. 권한(모드) 변경

```bash
sudo chmod 664 <파일>                # 숫자 지정
sudo chmod g+w <파일>                # 그룹 쓰기 추가 (기호 방식, 안전)
sudo chmod g-w <파일>                # 그룹 쓰기 제거
sudo chmod -R g+w <TARGET>
sudo chmod +x <SCRIPT>               # 실행 권한 추가
sudo chmod g+s <TARGET>              # setgid: 새 파일이 디렉터리 그룹 상속 ★
sudo chmod +t <TARGET>               # sticky: 소유자만 삭제 가능 (실수 방지)
```

### 디렉터리와 파일에 다른 권한 주기 (중요)

`chmod -R 664`를 디렉터리에 걸면 `x`가 사라져 디렉터리에 못 들어갑니다. **반드시 분리해서 적용하세요.**

```bash
sudo find <TARGET> -type d -exec chmod 2775 {} +   # 디렉터리 → 775 + setgid
sudo find <TARGET> -type f -exec chmod 664 {} +    # 파일 → 664
```

또는 대문자 `X`를 쓸 수 있습니다. 단 `X`는 **"디렉터리 + 이미 실행 권한이 있는 파일"**에 적용되므로, 실행 파일(.sh, .py)이 섞여 있으면 그 파일에도 그룹 실행 권한이 붙습니다.

```bash
sudo chmod -R g+rwX <TARGET>        # 편하지만 실행파일에도 x가 붙음
```

> **함정:** 최상위 디렉터리에 `x`가 없으면 `find`가 하위로 내려가지 못해 `Permission denied`와 함께 **일부만 적용되고 끝납니다.** 이럴 때는 최상위부터 먼저 열어주세요.
> ```bash
> sudo chmod u+rwx,g+rwx <TARGET>
> sudo find <TARGET> -type d -exec chmod 2775 {} +
> sudo find <TARGET> -type f -exec chmod 664 {} +
> ```
> 적용 후 `find <TARGET> -type d ! -perm -g+w` 로 누락분을 확인하면 확실합니다.

## 6. umask — 앞으로 만들 파일의 기본 권한

```bash
umask                               # 현재 값 확인 (0022 = 644/755)
umask 002                           # 이 셸에서만 664/775로
```

**영구 적용** (다음 로그인부터)

```bash
echo 'umask 002' >> ~/.bashrc
source ~/.bashrc                    # 지금 셸에 즉시 반영
```

| umask | 새 파일 | 새 디렉터리 | 용도 |
|---|---|---|---|
| 022 | 644 | 755 | 기본 (그룹 수정 불가) |
| **002** | **664** | **775** | **그룹 협업 (권장)** |

> **핵심 구분:** 새 파일의 **그룹**은 setgid가, **쓰기 비트**는 umask가 결정합니다. 둘 다 설정해야 `-rw-rw-r-- ... <GROUP>`이 나옵니다.

## 7. 그룹 협업 디렉터리 세팅 (레시피)

```bash
sudo chgrp -R <GROUP> <TARGET>                     # 1. 그룹 지정
sudo find <TARGET> -type d -exec chmod 2775 {} +   # 2. 디렉터리: 그룹쓰기+setgid
sudo find <TARGET> -type f -exec chmod 664 {} +    # 3. 파일: 그룹쓰기
echo 'umask 002' >> ~/.bashrc                      # 4. 이후 생성물도 664/775
sudo setfacl -d -m g:<GROUP>:rwx <TARGET>          # 5. 기본 ACL: umask와 무관하게 신규 파일도 그룹 rwx
```

**기존 root 소유 파일을 그룹 공용으로 전환**

```bash
find <TARGET> -user root -printf '%p\n' | head     # 대상 확인
sudo chgrp -R <GROUP> <TARGET>
sudo find <TARGET> -type f -user root -exec chmod g+w {} +
```

## 8. 권한 오류 진단 (PermissionError / Permission denied)

```bash
id                                  # 내가 그 그룹인가
ls -ld <TARGET>                     # 디렉터리에 그룹 w가 있는가
namei -l <TARGET>/<파일>             # 중간 경로에 x가 빠졌는가 ★
sudo -u <USER> touch <TARGET>/test   # 해당 계정으로 실제 쓰기 테스트
sudo -u <USER> cat <파일> > /dev/null # 읽기 테스트
df -h .                             # 디스크 풀도 쓰기 실패 원인
touch t_$$ && rm t_$$ && echo WRITE_OK   # 순수 쓰기 테스트 ★
getenforce; lsattr -d .             # SELinux / immutable 속성
```

| 증상 | 원인 | 조치 |
|---|---|---|
| 파일 생성 불가 | **디렉터리**에 `w` 없음 | `chmod g+w <디렉터리>` |
| 디렉터리 진입 불가 | 경로에 `x` 없음 | `chmod g+X`, `namei -l`로 확인 |
| 기존 파일 수정 불가 | 파일이 644이거나 다른 소유자 | `chmod g+w <파일>` 또는 `chown` |
| 그룹 추가했는데 안 됨 | 세션에 미반영 | **재로그인** 또는 `newgrp <GROUP>` |
| 새 파일이 계속 644 | umask 022 | `umask 002` |
| 새 파일 그룹이 계속 root | setgid 없음 | `chmod g+s <디렉터리>` |

> **꼭 기억할 두 가지**
> 1. **삭제·이름변경 권한은 파일이 아니라 상위 디렉터리의 `w`에서 나옵니다.** 디렉터리가 775면 그룹원이 남의 644 파일도 지울 수 있습니다 → 걱정되면 `chmod +t`.
> 2. **파일 소유자는 생성 시점에 그 프로세스 계정으로 고정됩니다.** 나중에 다른 계정이 append 해도 소유자는 바뀌지 않습니다.

**vi 저장 실패 시 에러 메시지로 원인 구분**

| 메시지 | 원인 | 확인 |
|---|---|---|
| `E212: Can't open file for writing` | 권한 | `ls -ld .`, `id` |
| `E514: write error (file system full?)` | 디스크 풀 | `df -h .` |
| `Read-only file system` | ro 마운트 | `mount \| grep <마운트지점>` |
| 권한은 맞는데 거부 | SELinux / immutable | `getenforce`, `lsattr -d .` |

- `:w!`는 vi 내부 readonly 플래그만 무시하며 **커널 권한 검사는 넘지 못합니다.**
- 편집 내용을 살리려면 쓰기 가능한 곳에 우회 저장: `:w /home/<USER>/<파일명>`

## 9. 계정·그룹 관리

### 계정 생성

```bash
sudo useradd -m -s /bin/bash -c "홍길동" -G <그룹1>,<그룹2> <NEW_USER>
sudo passwd <NEW_USER>
```

| 옵션 | 의미 |
|---|---|
| `-m` | 홈 디렉터리 생성 |
| `-s /bin/bash` | 로그인 셸 지정 |
| `-c "..."` | 설명(실명 등) |
| `-G a,b` | 보조 그룹 지정 (쉼표 구분, 공백 없이) |

### 그룹 추가·제거

```bash
sudo usermod -aG <추가그룹> <USER>   # 보조 그룹 추가 (-a 빠지면 기존 그룹이 전부 교체됨 ★)
sudo gpasswd -d <USER> <GROUP>      # 계정을 특정 그룹에서만 빼기
sudo groupadd <GROUP>               # 그룹 생성
id <USER>                           # 확인 (반영은 재로그인 후)
getent passwd <USER>                # 계정 정보
```

- `ls -l`에서 소유자가 이름이 아닌 **숫자(UID)**로 보이면 `/etc/passwd`에 없는 계정입니다.
  컨테이너가 `runAsUser`로 쓰는 UID인 경우가 많습니다.

### 그룹 자체를 삭제할 때

`groupdel`은 계정에서 빼는 게 아니라 **그룹 자체를 지웁니다.** 어떤 계정의 기본(primary) 그룹이면 삭제가 거부되므로 먼저 기본 그룹을 바꿉니다.

```bash
sudo usermod -g <새 기본 그룹> <USER>  # 1. 기본 그룹 변경
sudo groupdel <삭제할 그룹>            # 2. 그룹 삭제
id <USER>                            # 3. 확인
```

### 계정 잠금·삭제

```bash
sudo usermod -L <USER>              # 로그인 잠금 (삭제 대신 우선 권장)
sudo usermod -U <USER>              # 잠금 해제
sudo userdel <USER>                 # 계정 삭제 (홈은 남김)
sudo userdel -r <USER>              # 홈 디렉터리까지 삭제 (되돌릴 수 없음)
sudo chage -l <USER>                # 비밀번호 만료 정보
last <USER> | head                  # 최근 로그인 이력
```

## 10. sudo 권한 관리 (`/etc/sudoers.d`)

`/etc/sudoers.d/` 아래에 파일 단위로 sudo 사용자를 관리합니다. 파일 하나에 여러 명을 넣을 수 있고(예: 특정 용도별 목록 파일), **삭제할 때 파일만 지우면 되어 관리가 편합니다.**

### 현행 방식 먼저 확인

​```bash
sudo -l                                   # 내가 쓸 수 있는 sudo 명령
sudo grep -vE '^#|^$' /etc/sudoers
sudo ls -l /etc/sudoers.d/ && sudo cat /etc/sudoers.d/*
​```

`wheel`(RHEL 계열)·`sudo`(Debian 계열) 그룹은 `/etc/sudoers`의 `%wheel ALL=(ALL) ALL`
한 줄이 부여하는 권한이며, 그룹 자체에 특권이 있는 것이 아닙니다.

​```bash
sudo usermod -aG wheel <USER>     # 전체 권한 부여 — RHEL 계열
sudo usermod -aG sudo  <USER>     # Debian 계열
​```

### 권장 방법 — `visudo` 사용

```bash
sudo visudo -f /etc/sudoers.d/<파일명>   # 저장 시 문법 검사까지 해줌 ★
sudo visudo -c                          # 전체 sudoers 문법 검사
sudo -l -U <USER>                       # 해당 계정의 sudo 권한 확인
```

### 기존 파일을 복사해서 만드는 경우

```bash
cd /etc/sudoers.d
sudo cp <기존파일> <새파일>        # 1. 복사
sudo chmod 640 <새파일>            # 2. 편집 가능하게
sudo vi <새파일>                   # 3. 편집
sudo chmod 440 <새파일>            # 4. 원래 권한으로 복구 (필수)
sudo visudo -c                    # 5. 문법 검사 (필수) ★
```

### 작성 예시

```
# 계정 단위
<USER>    ALL=(ALL) ALL
# 그룹 단위 (% 접두사)
%<GROUP>  ALL=(ALL) ALL
# 특정 명령만 허용
<USER>    ALL=(root) /usr/bin/systemctl restart <SERVICE>
```

### 제한된 명령만 부여 (alias 템플릿)

​```
# <용도> (작성: YYYY-MM-DD)
User_Alias   <ALIAS_U> = <USER1>, <USER2>
Cmnd_Alias   <ALIAS_C> = /usr/local/bin/<CMD1>, /usr/local/bin/<CMD2>
Defaults:<ALIAS_U> secure_path = /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
<ALIAS_U> ALL=(root) NOPASSWD: <ALIAS_C>
​```

> **주의**
> - sudoers 문법 오류가 있으면 **sudo 전체가 동작하지 않아** 복구가 어려워집니다. 저장 후 반드시 `visudo -c`.
> - 파일명에 `.`이나 `~`가 들어가면 sudo가 **무시**합니다 (예: `list.bak`는 적용 안 됨).
> - 권한은 `440`, 소유자는 `root:root`여야 합니다.
> - 작업 중에는 root 셸을 하나 열어둔 채로 다른 창에서 테스트하면 안전합니다.
> - `/etc/sudoers.d/` 파일은 이름순으로 전부 읽힙니다. **같은 alias 이름이 여러 파일에 있으면
>   먼저 읽힌 쪽만 적용**되고 나중 것은 버려집니다 → 나중 파일에만 있는 계정이
>   `is not in the sudoers file`. 해결: 파일 통합 또는 alias 이름을 파일마다 고유하게.
>   중복 찾기: `sudo grep -n '<ALIAS_U>\|<ALIAS_C>' /etc/sudoers.d/*`
> - **사용자 홈 아래 스크립트를 NOPASSWD로 허용하지 마세요.** 사용자가 내용을 바꿔
>   무인증 root 상승 경로가 됩니다 → root 소유 경로(`/opt/...`)로 옮긴 뒤 등록.
> - `kubectl`, `k9s`, `ctr`, `crictl` 등을 sudo로 허용하면 **사실상 root 전체 권한**입니다.
>   조회 목적이면 sudo 대신 RBAC + 전용 kubeconfig 발급이 정석입니다.

### 다문자 구분자 로그 파싱

구분자가 **정규식 특수문자**(`| ^ . $ * + ? ( ) [ ] { }`)를 포함하면 `awk -F`에서 각 문자를 `\\`로 이스케이프해야 합니다.

```bash
awk -F'<이스케이프한DELIM>' '{print $2, $4, $7}' <로그>
awk -F'<이스케이프한DELIM>' '{print NF; exit}' <로그>           # 필드 개수 확인
awk -F'<이스케이프한DELIM>' '{c[$7]++} END {for (k in c) print k, c[k]}' <로그>   # 7번째 필드 집계
```

**더 안전한 방법 — 탭으로 치환 후 파싱** (이스케이프 실수 방지)

```bash
sed 's/<DELIM>/\t/g' <로그> | awk -F'\t' '{print $2, $7}'
```

## 16. 시스템·네트워크 상태 점검

```bash
hostnamectl                         # 호스트명, OS, 커널
uname -r                            # 커널 버전
cat /etc/os-release                 # 배포판 정보
uptime                              # 가동 시간, load average
free -h                             # 메모리
top                                 # 실시간 자원 (htop이 있으면 더 편함)
nproc                               # CPU 코어 수
df -h                               # 디스크 (자세한 분석은 디스크_용량_분석.md)
df -Th                              # 파일시스템 타입 포함
lsblk -f                            # 디스크·파티션·파일시스템·마운트 지도 ★
lsblk -e7                           # loop 장치 숨김
swapon --show                       # swap 현황
timedatectl                         # 시각 동기화 (로그 타임스탬프 정합성)
systemctl list-unit-files --state=enabled   # 부팅 시 자동 시작 서비스

ip a                                # IP 주소
ss -tlnp                            # 열린 TCP 포트 + 프로세스 ★
ss -tnp | grep <PORT>               # 특정 포트 연결 상태
ping -c 4 <HOST>                    # 응답 확인
nc -zv <HOST> <PORT>                # 포트 접근 가능 여부 ★
curl -I http://<HOST>:<PORT>        # HTTP 응답 헤더만
curl -sk https://<HOST>/<경로>       # 인증서 검증 없이 조회 (내부 테스트용)
nslookup <도메인>                    # DNS 조회
ip -4 -br a                         # 인터페이스별 IP 요약
ip -4 -br a | grep -vE 'cali|tunl|flannel|docker|veth|cni|lo'   # 컨테이너 IF 제외 ★
ip route get 1.1.1.1                # 외부로 나갈 때의 소스IP·GW·IF ★
ip route show default               # 기본 게이트웨이
curl -L ifconfig.me                 # NAT 변환 후 공인 IP
dig +short myip.opendns.com @resolver1.opendns.com   # HTTP 차단 환경 대안
sudo iptables -t nat -S             # 이 서버가 NAT를 수행하는지
firewall-cmd --list-all             # firewalld 규칙
```

- `lsof`·`du` 출력의 `DEVICE 8,17` 같은 번호는 `lsblk`의 `MAJ:MIN` 컬럼과 대조해 장치를 식별합니다.
- **swap**은 RAM 부족 시의 완충 장치이지 성능 증설 수단이 아닙니다. 쿠버네티스 노드는 보통 swap 비활성화가 요구사항이며, swap은 `df`/`du`에는 안 나오고 `lsblk`에만 보입니다.

### 사설 IP 대역 (RFC 1918)

| 대역 | CIDR |
|---|---|
| 10.0.0.0 – 10.255.255.255 | `10.0.0.0/8` |
| 172.16.0.0 – **172.31**.255.255 | `172.16.0.0/12` |
| 192.168.0.0 – 192.168.255.255 | `192.168.0.0/16` |

- `172.0~172.15`, `172.32~172.255`는 **공인 IP**입니다. 정규식으로 `172\.\d+\.` 전체를 내부로 간주하면 오분류가 납니다 → `172\.(1[6-9]|2[0-9]|3[01])\.`
- `169.254.0.0/16`(링크로컬), `100.64.0.0/10`(CGNAT)은 사설도 공인도 아닌 별도 취급입니다.
- 서버 IP가 사설이면 NAT 변환 주소는 상위 장비(방화벽)에 있으며 서버 안에서는 확인할 수 없습니다.

## 19. 자주 쓰는 리다이렉션

```bash
<명령> > <파일>                # 표준출력을 파일로 (덮어쓰기)
<명령> >> <파일>               # 표준출력을 파일에 이어쓰기
<명령> 2>/dev/null            # 에러 숨김 (조사 중에는 원인을 놓칠 수 있음)
<명령> 2>/tmp/err.log         # 에러 보존 — 조사 시 권장 ★
<명령> > <파일> 2>&1           # 정상 출력 + 에러를 같은 파일로
```

- 파일 디스크립터 번호: `0`=stdin, `1`=stdout, `2`=stderr
- `/dev/null`은 쓰면 버려지고 읽으면 EOF를 반환하는 표준 문자 장치(`c 1,3`)입니다.
- `ls -l /dev/null`이 `c`가 아닌 `-`(일반 파일)로 보이면 누군가 삭제 후 재생성된 상태입니다. 복구:
  `sudo rm /dev/null && sudo mknod /dev/null c 1 3 && sudo chmod 666 /dev/null`

## 20. 실수 방지 체크리스트

- `chmod -R 664`를 **디렉터리에 쓰지 마세요.** `x`가 날아가 진입 불가 → `find -type d/f` 분리
- `-R`로 소유자·권한을 바꿀 때는 **먼저 `find`로 대상 확인**
- 데몬이 사용하는 경로의 권한 변경은 **서비스 동작에 영향**을 줄 수 있음 → 담당자 확인
- `usermod -G`만 쓰면 기존 보조 그룹이 **전부 사라짐** → 반드시 `-aG`
- 그룹 추가 후 **재로그인** 필요 (`id`로 반영 확인)
- sudoers 수정 후 **`visudo -c`로 문법 검사**, 권한 440 복구
- `pkill -f`는 패턴이 넓으면 자기 셸까지 죽임 → **반드시 `pgrep -af`로 먼저 확인**
- `kill -9`는 파일이 잘릴 수 있음 → 먼저 일반 `kill`
- `find ... -delete`, `rm -r`, `userdel -r`은 되돌릴 수 없음 → `-print`/`ls`로 먼저 확인
