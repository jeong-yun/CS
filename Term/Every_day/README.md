# 🛡️ Next-Gen AI Security & Architecture Roadmap

본 리포지토리는 클라우드 인프라부터 인공 초지능(ASI) 시대의 에이전트 보안까지, 차세대 IT 환경에서 필수적인 보안 기술과 개념을 정리한 가이드입니다.
이 문서는 **작성 조건(분류·태그·형식·통합 규칙)** 만 담습니다. 개념 요약은 **[0. Summary.md](0.%20Summary.md)** 에 있습니다.

## 🗂️ 분류 기준 (최상위 분류)

분류는 그 개념의 **핵심 목적과 작동 층위**로 정합니다. 적용 대상(예: 클라우드)이 아니라 *무엇을 위해 존재하는가* 가 기준입니다.

| 분류 | 넣는 것 | 예 |
|---|---|---|
| **1. Cloud & Infrastructure** | 시스템·데이터·서빙 인프라의 아키텍처와 성능 (커널·네트워크·스트리밍·DB 엔진·LLM 서빙·분산 학습 인프라) | eBPF CNI, Kafka, ClickHouse 시퀀스 매칭, RadixAttention, 컨텍스트 캐싱 |
| **2. Artificial Intelligence** | 모델·학습·추론 알고리즘과 AI 시스템 설계 (아키텍처, 정렬·강화학습, 추론 스케일링, RAG·에이전트) | MoD, GRPO, TTSL, 에이전틱 RAG |
| **3. Security & Trust** | 공격·방어, 프라이버시, 신뢰(증명·무결성), 보안 거버넌스 | 프롬프트 인젝션, 기밀 컴퓨팅(TEE), 영지식 증명, CNAPP, N2SF |

- 보안에 *쓰이는* 범용 엔진·성능 기법은 Cloud & Infra, 그 기법으로 위협을 *탐지·대응하는 방법론* 은 Security & Trust 에 둡니다.
  (예: ClickHouse FSM 시퀀스 매칭 = Cloud, 시퀀스 기반 APT 위협 헌팅 = Security)
- 애매하면 옮기지 않고, 옮길 때는 이유를 남깁니다.

## ✍️ 항목 작성 형식

```
[태그]한글명(English, 약어) (작성일: YY.MM.DD)(수정일: YY.MM.DD, MM.DD)
1. 정의 및 개념      — 등장 배경(① 무엇이 문제였나 → ② 왜 실패했나 → ③ 어떤 처방인가) 2~4줄 포함
2. 작동 원리
3. 좋아진 점
4. 문제점            — 부적합 도메인·운영 오버헤드를 구체적으로 (장점 재진술 금지)
5. 사용 예시         — 문서화된 실사례(URL) 우선, 없으면 '응용 추정(비문서화)'
6. 관계(기존 개념과 비교) — 대상별 `· **대상**: 유사: … / 차이: … / 경계: …`
7. 변형·확장 상세     — (해당 시) 하위 항목마다 개념 / 작동원리 / 장점 / 단점(고유) / 예시
참고문헌             — `[유형 라벨] 저자·기관. 제목 (게재처·식별자, URL): 이 문헌이 본문의 무엇을 뒷받침하는가`
```

- **문체**: 개조식(명사형 종결: ~함 / ~됨 / ~임 / 명사구). 원전 직접 인용만 예외.
- **수치**: 측정 조건(벤치마크·워크로드)을 함께 적고, 본문 수치는 참고문헌 요약에도 적습니다.
- **금지**: 출처 불명 수치, 플레이스홀더 인용(가짜 arXiv ID·URL), 절대 표현(완벽·100%·무조건·완전 차단).
  확인되지 않은 내용은 "확인되지 않음"으로 적습니다.
- **참고문헌 라벨**: [논문·핵심기법] / [논문·서베이] / [논문·한계·반박] / [논문·벤치마크] / [표준/거버넌스] / [도구/프레임워크]
- 표제어는 통칭 수준으로, 세부 한정어는 부제로. 한글·영문 개념명을 일치시킵니다.
- 전문 용어는 처음 나올 때 괄호로 풀이하고, 반복해서 필요한 기초 지식은 `basic_Term.txt` 에 한 줄로 추가합니다.

## 🔗 통합 규칙 (새 개념이 기존 개념과 겹칠 때)

1. 초안의 배치·계보 주장은 *주장* 일 뿐 — 각 개념의 원전을 따로 확인하기 전에는 받아들이지 않습니다.
2. **이중 해리 검사**: "A는 B 없이 성립하는가?" / "B는 A 없이 성립하는가?" → 둘 다 '예'면 축이 다른 개념 → **별도 항목 + 상호참조**.
3. 판정
   - 같은 개념을 두 번 작성 → **병합** (풍부한 쪽을 남기고 고유 정보 흡수)
   - 원리·메커니즘이 같고 조건·모달리티·손실함수·파라미터·하드웨어만 다름, 또는 상위 개념의 구성요소 → **편입** (부모의 `7. 변형·확장 상세`)
   - 원리 자체가 다름 → **별도 + 상호참조** ("자체 논문·도구가 있다"는 분리 사유가 아님)
   - 3단 중첩(변형의 변형) 금지 — 생기면 부모를 잘못 고른 것
4. 통합으로 빠지는 항목의 원문은 `old_term.txt` 로 옮기고, 그 개념을 가리키던 다른 항목의 문장(관계·참조)도 함께 고칩니다.
5. 실패 선례: GRPO 를 RLVR 의 확장 상세로 편입한 것은 오류 — GRPO 원전은 학습된 보상 모델, RLVR 원전은 PPO 를 썼음(축이 직교).
